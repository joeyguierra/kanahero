0MSGOT IT. The ghost is cloned off the prompt card's box, face down, position:fixed, z 25, no pointer events.

The counts lag by one flight on purpose. They are their own state, written when the ghost lands — so the header can say DECK 6 · HAND 3 while the queue and the prompt have already moved to the next word. Cancelling the flight (a fast second GOT IT) lands it immediately rather than dropping the tick.

WHAT HE SAYS, AND WHEN

One rule, not four branches — the caller picks the screen, the engine gives a due aside precedence over it:

missed → once (global or set) → earned.<rarity> → round.kana | round.kanji

The earned.* line is spoken on the next prompt, not on the card just graded — and it carries {tries} for the card he is talking about, not the one in front of him. The prompt after that returns to round.*. An aside waves it off for that prompt; the reveal and a miss wave the aside off.

HOW A CARD IS BUILT

One slot, two faces, backface-visibility:hidden, the slot rotated 180° on Y. Both faces are in the slot from the first frame, so a card landing face up reflows nothing. The fan's angle is written into the same transform (.fanCard2.revealUp = rotate + rotateY), and the perspective lives on the container at 900px.

The fan's overlap moved to the slot and its padding stayed on the card — .fanCard + .fanCard{margin-left:-34px}, .fanCard + .fanCard .card{padding-left:36px}. S8 turns the slot, so the two cannot share an element.

THE SWEEP IS INSIDE THE CARD

.revealSweep .card::after, a 105° white gradient translating −120% → 120% in 400ms, drawn inside the card so the card's own clip — notched corner and all — is what the shine runs behind. On the wrapper it escaped the edge. Afterwards the card rests with the shiny finish it would have had anyway: shiny stays the only glowing thing on the screen and never glows harder than it did before.

SKIP

A tap anywhere but BACK TO DECK jumps to the end state: every face up, final counts, no sweep, his line starts. After the reveal, a tap on a card opens the face overlay as before. // sfx: reveal.skip

THE ORDER IS THE LAYOUT

Worn → base → shiny, grading order within a stock — and the layout uses the same order, so the reveal sweeps left to right, top to bottom, and the best card of the run lands at the end of it. In the fan that means the shiny is the right-hand card, on top.

THE FAN CHIP KEEPS ITS NUMBER

SHINY · 1, WORN · 4 — the fan and the overlay face are the only places a try count prints, because it comes from the run's own state on the way out. Nothing stores it.

WHAT S8 STILL OWES

The count and the tally tick with the faces, but they tick as plain text — no motion of their own. The 64px number is the loudest type in the app and currently the quietest thing on the screen. See M11 in the motion lab.

RULESWhat the app is now — the part the animations have to stay true to

THE RUN

All-or-nothing. Nothing about a run reaches storage until the queue empties. Abandoning, reloading or closing mid-run discards every card in the hand. One write at the end, earnRun(), every word of it — and it happens before S8 mounts, so the reveal is presentation only. Leaving mid-reveal costs nothing.

The whole set, every time, in a seeded random order. A set is always replayable; "nothing left to deal" does not exist. A miss goes back in the queue with a gap of 2.

Tries live in the round and die with it. 1 try → shiny · 2 → base · ≥3 → worn, fixed when the card is graded.

The reward is at the end. One word earns one 260ms ghost and a count tick. The run earns S8.

THE WORD

foil is gone everywhere. It is shiny. minted is gone everywhere — UI, code, comments, tests. It is earned. Progress.earned is a different, older thing (the drill's written-from-memory set) and did not change.

During a run the hand is provisional and nothing may say otherwise — no label, no line, no rarity. The word EARNED appears exactly once per run, on S8, after the run is already written.

THE PANELHow a line is chosen — the constraints any panel animation inherits
THE JOKER'S PANEL IS ON EVERY SCREEN AND IS NOW THE MOST DYNAMIC ELEMENT IN THE APP. THESE FOUR FACTS DECIDE WHAT AN ANIMATION ON IT CAN ASSUME.

1 · IT IS FULL HEIGHT BEFORE THERE IS A LINE

.jokerLine reserves min-height:2.9em — two lines, always. Under twelve words never wraps past two, so the panel is the same height whichever line he draws, and the same height when he has drawn nothing at all. Nothing below the panel may move when a line arrives.

2 · THE LINE ARRIVES LATE, AND SOMETIMES NOT AT ALL

It depends on localStorage and this is a static export, so nothing is drawn until storage has landed: S1 mounts with an empty panel. On S8 he is deliberately silent until the last card lands. A panel animation triggered by "line changed" fires on neither.

3 · ONE DRAW PER BEAT

useJokerLine(screen, ctx, beat) picks once per beat and commits in an effect — a re-render never re-draws, and a screen he is not on (null) draws nothing and spends nothing. The type-on restarts only when the id actually changes.

4 · HE NEVER REPEATS UNTIL HE HAS TO

A shuffle bag per screen, persisted: an ordered list of ids still to come. A conditional line that is not eligible right now keeps its place rather than being burned. When the corpus changes, new ids go in at the front — after an update he says the new things first.

THE ORDER OF PRECEDENCE

missed → once (global or set) → earned.<rarity> → round.kana | round.kanji

One rule in one place: the caller picks the screen, an eligible once line outranks it. Asides are opt-in per screen — the round asks for them, the home screen does not, which is why "Whole word, one box" can no longer turn up on S1.

TOKENS

{bank} {shiny} {earned} {words} {chars} {tries} {n:X} — rendered as words ("Seven"), digits past twenty-one, capitalised at the start of a line. A token with no value makes the line ineligible: never a blank, never a zero he did not mean.

WHAT THE PANEL PUBLISHES

.jokerPanel[data-line] carries the corpus id — the e2e asserts on ids, never on his wording, and so should any tool that has to find a specific line on screen.

WHERE THE WORDS LIVE

joker/corpus.md (global) and public/sets/*.json under a joker key (set-scoped, drawn at 3× weight). Never in a component. Ids are forever; the wording behind an id may change any time, so do not draw a line into a comp and call it fixed.

HOW TO USE THIS SHEET

Every artboard is the shipped tree at e3cd9e3, not a wish — except the one stamped DELETED, which is drawn once so nobody redraws it. Draw on top of these: a motion slot wants three frames and a curve, an overlay slot wants one artboard at 390×844 with the layer over a real screen. Anything that changes a number, a line or a rule belongs in a spec first.

Four things that must survive any animation: the canvas never moves or resizes between prompt and reveal · the Joker's panel never changes height, with or without a line in it · a card slot never reflows when its card turns · nothing says a card is kept, earned or shiny before the run finishes.

And one that is new: every beat in a run is now non-blocking. The melt, the flight, the tick and the reveal can all be interrupted by the next input and none of them may swallow a tap.
