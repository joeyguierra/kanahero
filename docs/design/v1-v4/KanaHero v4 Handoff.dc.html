THE ONE SEMANTIC RULE

A card is earned, never shown. Before the first correct write the word exists only as a prompt. The kanji's first appearance anywhere in the app is as the earned face — which is why the reveal on S7b paints the model on the canvas, over your ink, and not onto the card.

Rarity is tries, and tries are permanent. 1 = foil, 2 = standard, 3+ = worn. Written on the face, fixed at the moment of the first correct write, never upgraded by a later replay. A requeue does not reset the counter.

Nothing is learned by recognition. No multiple choice, no tap-to-match, no "which of these", ever — in any build. The only input is handwriting.

SPEC v4 flows, layout law, and scope guard
FLOWS
F10 · ENTER THE ROUND

S1 → tap JOKER card → S6 → tap the set row (or OPEN STATION) → S6b → DEAL → S7. Four taps from cold start to writing, all in the lower two thirds of the screen. The Joker card and the bank strip are siblings on S1, not a menu.

F11 · THE LOOP (UNCHANGED MECHANIC, NEW SHELL)

Prompt dealt → write on the 334px canvas → FLIP → model over ink → GOT IT / MISSED. Got it → earned face in place, slide to hand, deck−1, hand+1, attempt count frozen. Missed → back into the deck at the far end, attempt count +1 on its next appearance, no animation, no penalty copy. Round ends when the deck hits 0 → S8. There is no quit-with-score: ✕ abandons the round and keeps the cards already earned.

F12 · RESULT AND RE-ENTRY

S8 → BACK TO JOKER → S6, set row now reads its new fraction. Dealing a completed set deals only the cards not yet earned; a set at 12/12 shows the hand instead of DEAL. Nothing about the round is stored except per-card {tries, earnedAt, rarity}.

LAYOUT LAW

Thumb zone: every primary action sits in the bottom 240px, full width, chamfered bottom-left — same species as START SESSION and CAPTURE. Strike fill = the act of drilling (DEAL, FLIP). Bone fill = leaving or reviewing (OPEN STATION, BACK TO JOKER). Green/amber = self-grade only. Fans may bleed past the screen edge — stock only. Card content never does: it is inset away from whichever edge its neighbour covers, and no card text ever wraps.

BUILD NOTES
DATA SHAPE

Sets are content, shipped as JSON, never generated: sets/station.json → {id, place, glyph, name, words:[{kanji, reading, romaji, meaning, kind}]}. Progress lives beside the existing store: kanahero:v1.joker[setId][wordId] = {tries, rarity, earnedAt}. No set state, no round state persisted — an abandoned round is simply the cards it already wrote.

DEALER

One module, lib/joker.ts: takes the unearned word list, returns a queue; miss() pushes to the tail with a minimum gap of 2 so a missed card never comes straight back. Shuffle is seeded per round for reproducible bug reports. The dealer holds no difficulty model, no spaced repetition, no scheduling — that is the v5 question, deliberately unanswered.

MOTION BUDGET

Exactly two: the flip (existing reveal, unchanged) and the slide (earned card to the hand strip, ~260ms, one ease, no bounce, no particles, no sparkle on foil beyond its static glow). Both respect prefers-reduced-motion by cutting to the end state. Nothing else animates, ever.

REUSE

S7's canvas, grading ladder, stroke overlay and CLEAR/UNDO are the S2/S3 components as-is — if the round needs a canvas change, the change belongs to S2 first. The card component is new and shared by S6b, S7, S7c and S8 at four sizes; one component, one anatomy, size-driven type ramp.

SCOPE GUARD — NOT BUILT, NOT DRAWN

One set only · no other jokers · no HP, turns, damage, opponents · no card effects or combos · no audience decks · no OCR, no recognition mode of any kind · no sound · no timer · no share, streak, or score beyond the count · no set unlock ladder, nothing greyed, nothing "coming soon". Offline, localStorage, no account — unchanged.
