SPEC v3 flows, rules, and build notes
THE ONE SEMANTIC RULE

The bank is not a fourth track. Track cards are closed fractions — a denominator, a bar, an end state. The bank count has none of those: it is the only unbounded number in the app, it grows in the field, and its growth is the point. Binding consequences: never a progress bar on anything bank-related · never a track-card silhouette (the S1 entry is a strip, visually lighter) · the count renders in JetBrains Mono, strike — an instrument reading, not a score.

F6 · CAPTURE LOOP (FIELD CONDITIONS ARE THE SPEC)

S1 → tap BANK strip → S5 → CAPTURE → native camera → shutter → saved. Two in-app taps to the camera, zero after the shutter — no confirm, no annotate. Grid prepends, count ticks. Framing happens in the native camera; a confirm screen is a place to lose a capture to a closing train door.

F7 · REVIEW + NOTE (AT THE HOTEL)

S5 → tap thumb → S5b → read photo, add the one-line note ("where I was") → back. Notes are for the hotel table, never the escalator.

F8 · EXPORT — THE INSURANCE POLICY

S5 → EXPORT → one ZIP (STORE mode): captures/<id>.jpg + manifest.json → navigator.share, anchor-download fallback. Never mutates the bank; repeatable; idempotent. The ZIP is also the input format the later conversion build reads.

F9 · DELETE

Only in S5b, one in-place confirm, permanent. No multi-select, no clear-all — bulk destruction of a trip's irreplaceable data is not a button this app offers. The bank is a cul-de-sac: one button in (S1 strip), one back per screen, no path to or from a session.

BUILD NOTES
CAPTURE PIPELINE

<input type="file" accept="image/*" capture="environment"> behind the styled button — native camera, offline, no getUserMedia. On change: createImageBitmap(file, {imageOrientation:"from-image"}) (bakes EXIF rotation), downscale long edge to 1600px, toBlob("image/jpeg", 0.82), write to IndexedDB, prepend grid, tick count. Legibility beats bytes — raise the cap if station-board text isn't readable (open Q10, one evening's test on the real phone).

STORAGE SHAPE

Photos never touch kanahero:v1 — the number and the photos stay in separate failure domains. DB kanahero-bank v1, store captures, record {id, blob, w, h, bytes, takenAt, note}. One blob per capture; thumbs are object URLs from the same blob, revoked on unmount. navigator.storage.persist() requested on first capture; result surfaced honestly in the footer. New module lib/bank.ts mirrors the progress.ts store pattern so S1 subscribes to the count the same way.

SERVICE WORKER — V2'S GAP, NOW IN SCOPE

Generated by scripts/gen-sw.mjs after next build: walks out/, emits the full precache list under a content-hash cache name. Install → addAll + skipWaiting; activate → clean old caches + claim; fetch → cache-first, navigations fall back to the shell. Precaches the built app only — never IndexedDB, never captures, no sync, no push.

THE OFFLINE LAW, SCOPED

1 · Drilling fully offline, always. 2 · Capture fully offline, always. 3 · Conversion (future build) may touch network once, at conversion time, seated, by choice. 4 · $0 runtime, unchanged.

COUNT TICK (OPEN Q4)

The montage beat is shutter → grid gains a thumb → count ticks N → N+1. Two variants: flat (digit swaps, nothing else) or single flash — the digit renders one frame in strike-on-bone inverse, ≤200ms, no motion. Anything springier is retention theater. Recommend: flash on S5 (it's the filmed screen), flat on S1.

SCOPE GUARD — NOT BUILT, NOT DRAWN

No OCR/recognition/identify · no crop, rotate, edit · no tags, folders, search, sort · no multi-select, no clear-all · no geotagging · no cloud sync · no drill entry from the bank · no capture-time confirm screen. Kanji track stays designed-not-built on v2 terms; the bank feeds it in a later build (the trip's captures become an S1b preset whose denominator is the real bank size). Attribution gap (OFL text + Klee One notice in public/licenses/) and stale metadata fold into this build.
