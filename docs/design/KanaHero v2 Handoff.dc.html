SPEC Flows, deltas, and build notes
USER FLOWS
F1 · MAIN LOOP — IDENTICAL ACROSS TRACKS

S1 → pick track → (kanji only: S1b pick preset) → Start. Deck shuffles into a queue.
→ S2 prompt, blank canvas, you write it
→ Show → S3 card flips, ink dims, model animates over it
→ Got it / Missed → canvas clears, next card
→ queue empty → S4

F2 · REQUEUE

Missed reinserts ~5 positions later — far enough to clear short-term memory. Keeps returning until graded Got it. Unchanged for kanji.

F3 · DECK PICK — THE ONLY BRANCH

hiragana / katakana → base 46 ↔ all 71, inline on S1
kanji → S1b preset grid, one preset per session
Both remember the last choice.

F4 · WHAT MINTS THE NUMBER

A character is written from memory only on a first-attempt Got it within a session. A requeued clear does not count — you copied what you just watched. Cumulative per track, never decays. A character you fumble can only be earned in a later session: that is the spaced return.

F5 · INTERRUPTION

Closing mid-session discards the queue. Earned characters persist at the moment of grading, so nothing is lost. No resume.

DELTA AGAINST SPEC.MD

SPEC.md's “deliberately not building” list names kanji. That line is now spent, on the terms katakana was spent: same drill, same canvas, same self-grade, same stroke-animation mechanism. Everything else in that list stands — yōon, small kana, vocabulary, reading practice, recognition, hints, skip, streaks, percentages, accounts, nav bar, settings.

  • 4 screens → 5. S1b is the one addition, and only kanji reaches it. Kana still goes Home → session.
  • Home is a three-track switchboard rather than a single hero count. Each track carries its own progress; counts are never merged, per the spec's あ/ア argument extended to 漢.
  • Screens 2 and 3 keep the shipped mechanics exactly — Clear / Undo / Show, then flip-in-place with the model drawn over dimmed ink. Only the visual system changed.
  • One deck per session. No mixed kanji deck, no kana+kanji deck.
OPEN QUESTIONS
  • Kanji readings on the reveal — kun/on, or meaning only? Drawn here; cut if it reads as vocabulary study creeping into a writing app.
  • Preset size. 10–16 cards is drawn, roughly one train ride. Confirm before authoring real sets.
  • Homophone meanings. Several kanji share an English gloss. Either disambiguate the prompt or guarantee uniqueness within a preset.
  • The kanji denominator is the sum of all presets. If presets ever become user-addable the denominator moves — which the spec's argument against percentages would dislike. Fixed corpus recommended.
BUILD NOTES
DATA MODEL

lib/kana.ts → lib/decks.ts, one card shape for all three tracks:
{ id, track, char, prompt, strokeCount, deck } plus readings:{kun,on} on kanji only. prompt is romaji for kana and English meaning for kanji, so S2 renders one field and never branches on track.

Keep the existing derivation — katakana generates from the hiragana table by +0x60, never restated. Kanji is a separate authored table; meanings and readings cannot be derived.

PRESETS

A preset is { id, label, glyph, chars[] } in one JSON file. All six categories and their membership are placeholders — expect wholesale replacement. Do not hardcode six anywhere; the S1b grid is 1fr 1fr auto-flow and scrolls past eight.

PERSISTENCE

Same localStorage blob, version bumped. Earned characters stay a flat codepoint set — kana and kanji codepoints never collide, and each track counts its own. Add lastTrack and lastPreset beside lastSet.

STROKE DATA — THE ONE REAL DEPENDENCY CHANGE

strokesvg has no kanji. Kanji stroke data comes from KanjiVG, which SPEC.md already names as the kana fallback: centerline paths, one <path> per stroke in writing order, animates with the same dasharray technique. Two decisions before building:

  • License. KanjiVG is CC BY-SA 3.0 — share-alike reaching any derivative of the stroke data. It does not reach app code, but the vendored SVGs and anything generated from them stay under a compatible license, and Home's attribution line must name it (drawn in S1).
  • Look. KanjiVG renders a uniform hairline, not the brush-weight line strokesvg gives kana. Kana and kanji reveals will not match unless the kanji stroke is thickened and rounded — worth a call, exact parity may not be reachable.

ViewBox is 0 0 109 109 (KanjiVG) vs 0 0 1024 1024 (strokesvg) — normalize at vendor time so the overlay math stays one code path. Vendored to public/strokes/<codepoint-hex>.svg; the service worker precache list grows by the kanji count.

LOAD-BEARING, UNCHANGED

The canvas is square, 334×334 at 390 width, and holds the same box on S2 and S3 — the animation lands on top of your ink at the same size and position, so nothing may reflow between them. Concurrent animation of a group's repeated trajectories still applies; kanji have more self-intersecting strokes than kana, so the e2e-loop.mjs guard matters more, not less. Pointer Events, touch-action:none, DPR-sized backing store, all actions in the bottom third.
